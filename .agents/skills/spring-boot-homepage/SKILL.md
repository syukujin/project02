# Thymeleaf 홈페이지 제작

## 적용 범위

`src/main/resources/templates/index.html`을 기준으로 회사 소개 홈페이지를 구현한다. 사용자가 지정한 브랜드·콘텐츠·디자인을 우선하고, 기존 화면 구조는 재사용 가능한 출발점으로 삼는다. 스킬 생성·수정 요청만 받은 경우에는 애플리케이션 파일을 변경하지 않는다.

## 구현 전 확인

- 프로젝트 루트의 `AGENTS.md`, `README.md`, `build.gradle`을 확인한다. README는 수정하지 않는다.
- 다음 원본 파일을 읽고 실제 요청 경로, 템플릿 연결, 스타일, 이미지 의존성을 확인한다. 아래 경로는 프로젝트 루트 기준이다.
  - `src/main/resources/templates/index.html`
  - `src/main/resources/static/css/home.css`
  - `src/main/java/com/mycompany/project01/controller/HomeController.java`
  - `src/main/resources/application.properties`
- 현재 `GET /`는 `HomeController.home()`에서 `index` 템플릿을 반환한다. 기존 기본 패키지와 매핑을 재사용하고 동일한 `/` 매핑을 가진 컨트롤러를 추가하지 않는다.
- 현재 Java 21, Spring Boot, Gradle 설정을 유지한다. 홈페이지 표현만 바꾸는 작업에 DB·MyBatis·인증 의존성을 추가하지 않는다.

## 참고 화면 구성

| 영역 | index.html의 기준 | 제작 시 고려 사항 |
| --- | --- | --- |
| 문서 설정 | 한국어, UTF-8, viewport, Thymeleaf 네임스페이스 | 브랜드에 맞는 제목과 모바일 설정 |
| 본문 바로가기 | `.skip-link`에서 `#main`으로 이동 | 키보드 포커스 시 링크 표시 |
| 헤더 | 브랜드와 홈·회사 소개·핵심 가치·문의 메뉴 | 메뉴 링크와 대상 ID 일치 |
| 메인 배너 | `#home`, `.hero`, 배너 이미지와 소개 버튼 | 읽기 쉬운 제목, 명암 대비, 유효한 버튼 목적지 |
| 회사 소개 | `#about`, 소개 제목과 설명 | 사용자 제공 사실과 문구 반영 |
| 핵심 가치 | `#values`, 신뢰·도전·동반 성장 카드 | 항목 수와 내용은 요청에 맞게 조정 |
| 푸터 | `#contact`, 브랜드·문의 안내·저작권 | 실제 연락처가 없으면 준비 중 안내 유지 |

화면 상단의 `#div1`, `#div2`, `.myclass`는 현재 파일에 포함된 추가 콘텐츠다. 새 홈페이지의 필수 요소로 복제하지 않으며, 기존 화면을 수정할 때는 요청과 무관하게 삭제하지 않는다. 회사명, 연락처, 실적 등 확인되지 않은 정보를 실제 사실처럼 만들지 않는다.

## 화면 구현

- HTML은 `templates/index.html`에서 구현하고 정적 파일은 기존 `static` 경로를 사용한다. 기존 `home.css`와 `images/company-banner.png`를 먼저 재사용한다.
- `xmlns:th="http://www.thymeleaf.org"`를 유지한다. 리소스에는 `th:href="@{/css/home.css}"`, `th:src="@{/images/company-banner.png}"`처럼 Thymeleaf URL 표현식을 사용한다.
- 동적 문구는 모델로 전달하고 `th:text`로 출력한다. 사용자 입력을 그대로 `th:utext`에 넣지 않는다.
- `header`, `nav`, `main`, `section`, `article`, `footer`와 일관된 제목 계층을 사용한다. 이미지에 의미 있는 대체 텍스트를 제공하고 장식 요소는 보조 기술에서 제외한다.
- 기존 화면의 색상·여백·타이포그래피를 고려해 수정한다. Bootstrap을 도입하는 요청에서는 5.3 클래스를 우선하고 부족한 표현만 CSS로 보완한다.
- 기존 CSS의 모바일 분기인 760px 이하를 참고해 메뉴 줄바꿈, 소개 영역의 단일 열 전환, 가치 카드의 세로 배치를 구현한다. 작은 화면에서 가로 스크롤과 텍스트 잘림이 발생하지 않도록 한다.
- 부드러운 스크롤을 사용하면 `prefers-reduced-motion` 설정을 존중한다. 링크·버튼의 키보드 포커스를 보이게 한다.
- 단순한 페이지 내 이동에는 앵커 링크를 사용한다. 요청된 REST API 연동이 있을 때만 `fetch`를 추가하고 오류·로딩·빈 결과를 화면에 안내한다. 문의 접수 기능이 없는 버튼을 접수 가능한 것처럼 표시하지 않는다.
- 이미지 교체가 필요하면 사용자가 제공한 자료나 프로젝트 내 사용 가능한 자산을 우선한다. 디자인 참고 자료가 배포나 외부 업로드 권한을 부여하는 것으로 해석하지 않는다.

## 검증 및 결과 전달

- 변경 범위에 맞게 Gradle Wrapper로 빌드한다. 컨트롤러나 모델 처리까지 변경한 경우 관련 테스트도 실행한다.
- 애플리케이션 실행이 가능한 경우 `GET /`의 정상 응답과 템플릿 렌더링, CSS·이미지 요청을 확인한다.
- 브라우저 확인이 가능한 경우 데스크톱과 모바일 화면에서 메뉴 목적지, 버튼, 이미지, 가로 넘침, 키보드 포커스를 확인한다. 실행 중인 사용자 서버가 있으면 먼저 재사용한다.
- 실제 수행한 검증과 수행하지 못한 확인을 구분해 전달한다. 스킬 문서만 작성한 경우 애플리케이션 빌드·실행은 필요하지 않다.
- 결과에는 수정한 파일, 화면의 주요 변경 내용, 검증 결과를 간결하게 기록한다.
